# AI Boat Firmware v3.0.0

**Release date:** 2026-09-28

## Highlights

- Added Audio as a third control mode alongside Auto and Manual. Speech recognition runs in an external client; the ESP32 accepts the recognized text over HTTP.
- Added `POST /api/audio` for recognized commands such as `start`, `forward`, `stop`, `backward`, `left`, `right`, `servo left`, `servo right`, `straight`, `status`, and `auto`/`autonomous`.
- Added ultrasonic collision checks for manual and audio Forward/Left/Right commands. Close obstacles and sensor no-echo results stop/block the requested movement and return a reason.
- Limited Audio-mode reverse to a 750 ms pulse because the robot has no rear-facing sensor.
- Added asynchronous MQTT publishing using a dedicated FreeRTOS worker and a 16-entry event queue. MQTT TLS connection, reconnect, and publish operations no longer run in the navigation loop.
- Added event-triggered messages for boot, movement changes, mode changes, and manual sensor readings, plus periodic telemetry every 5 seconds.
- MQTT messages publish to `esp32/sensors` and include event name, movement, servo position, mode, distance, temperature, and humidity.

## Control Modes

- **Auto:** ESP32 runs the autonomous ultrasonic obstacle-avoidance state machine.
- **Manual:** Browser controls drive the motors and position the sensor; manual drive has a 900 ms command timeout.
- **Audio:** The ESP32 accepts text from an external speech-recognition client. `auto` or `autonomous` switches back to autonomous operation; `manual` switches to Manual mode.

The existing web page includes an Audio selector and a text-command field for testing without a microphone. Python, Android, or another client can send URL-encoded form data to `POST /api/audio` with a `text` field and read device state from `GET /api/status`.

## MQTT Event Format

Example payload:

```json
{
  "event": "periodic",
  "movement": "forward",
  "servo": "center",
  "mode": "auto",
  "distanceCm": 84,
  "temperatureC": 24.6,
  "humidityPercent": 58.0
}
```

Periodic and event-triggered snapshots share the same queue. If the queue fills while offline, the oldest queued snapshot is dropped so the newest device state can be retained.

## Compatibility and Safety

- The control page is unauthenticated; use it only on a trusted local Wi-Fi network and do not expose it to the public internet.
- Reverse movement cannot be collision-checked because there is no rear-facing sensor.
- MQTT broker credentials and Wi-Fi credentials must be kept private and configured for the target device.
